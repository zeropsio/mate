# Crew work after a restart

When Mate restarts during crew work, an update included, the crew carries on by itself once Mate is
back. Each crewmate picks up where its work stood:

- A turn the restart cut off continues in the same crew copy, in the same attempt.
- A turn that had just ended gets its work saved. Outside a run, nothing more happens until you
  message the crewmate. In a running run, the run carries the task on.
- A check runs again. A landing either records that the work is already in Fen's code or lands it
  again.
- A task waiting for your answer, for a review or for **Land** stays as it was.

A running crew keeps running. A crew you paused or stopped stays that way, and **Resume** carries
its work on. A request to show work on dev that you allowed goes out first.

Some work waits for you instead, and its row says why. That covers a copy you chose to rebuild, a
message you sent the lead yourself, and work Mate can no longer start for its signer. Press
**Continue** to carry it on, or **Drop it** to cancel an interrupted task before landing. Drop it
keeps the task's files in its copy.

Once a task's check has passed, its copy is never changed behind your back. If that copy has
edits after the check, the task stops and says so, and the edits stay in the copy. Nothing
unchecked lands.

A crew copy that went missing comes back by itself when its saved work is all still there. If some
of it is gone, the row names what was lost and shows **Rebuild crew copy**, which rebuilds only
that crewmate's copy from its saved work.

If a conversation has a different copy selected, it shows **Conversation points elsewhere** with
both paths. **Use crew copy** switches that conversation to its crew copy. Your selection stays in
place until you press it.
